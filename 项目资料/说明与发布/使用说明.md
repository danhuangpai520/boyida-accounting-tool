# 保谊达车队做账工具使用说明

## 1. 最简单分享方式

稳定版平时双击这个入口：

`做账执行工具.exe`

它旁边必须保留 `_internal` 运行库目录。默认使用在线 GLM-OCR，也可在 `OCR 引擎` 中切换阿里云、百度、腾讯云或本地 PaddleOCR；在线 OCR 不要求对方安装 Python、PaddleOCR、CUDA 或 5090 驱动环境。

如果要发给别人，默认稳定方式是把 `做账执行工具.exe` 和同级 `_internal` 文件夹一起打包成 zip 发送。这样可以避免单文件版首次自解压时被 Windows 拦截并弹出 `CreateProcessW: 拒绝访问`。

如果要给公司内部同事用安装包，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\项目资料\安装包\构建安装包.ps1
```

安装包默认装到 `%LocalAppData%\Programs\BoyidaAccountingTool`，创建开始菜单入口，并在程序目录旁创建 `扫描导入` 文件夹。卸载时可选择完整清理配置、扫描导入和程序生成数据，或保留业务文件只卸载程序。

如果业务上必须只发一个 EXE，请使用单文件分享版：运行 `项目资料\开发源码\设置内置Key并打包.ps1 -OneFile`，然后发送 `项目资料\单文件分享版\<构建时间>\做账执行工具.exe` 这一单个文件。发送前必须把这个 EXE 单独复制到空目录，确认 `--self-test`、`--startup-smoke-test` 和正常启动都通过。

在线 OCR 需要：

- 能联网；
- 手动填写自己的 ZHIPU API Key，或使用本机已保存的 Key；
- 如切换阿里云、百度、腾讯云 OCR，需要对应云厂商 Key；可通过环境变量、本机保存配置，或 `OCR 设置 -> 导入云 Key` 从本机私有 `API KEY` 文件夹导入；
- 图片单张不超过 GLM-OCR 官方限制。

公开发布版 EXE 默认不内置 API Key。智谱 Key 优先级是：环境变量 `ZHIPU_API_KEY` > 本机保存的 Key > EXE 内置默认 Key（仅私下打包时才可能存在）。阿里云、百度、腾讯云 Key 只允许来自本机环境变量、本机安全配置或本机私有 `API KEY` 文件夹。

默认公开打包不内置 Key，直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\项目资料\开发源码\设置内置Key并打包.ps1
```

如果以后只给内部指定人员做“内置默认 Key”的私下版本，才把 Key 放到 `builtin_api_key.txt`，并运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\项目资料\开发源码\设置内置Key并打包.ps1 -EmbedKey
```

打包完成后删除 `builtin_api_key.txt`。公开 GitHub Release 不使用 `-EmbedKey`。

每次打包都会自动在 `项目资料\版本备份` 里保存一份本地回退版本。稳定版备份包含根目录 exe、`_internal` 运行库目录、源码、执行规范、使用说明和 SHA256 校验信息；单文件分享版备份会标记为 `onefile`；备份不会保存明文 API Key。

## 2. 最终输出

软件固定生成：

`运输录入_<日期范围>.xlsx`

Excel 固定包含：

- `运输录入`
- `重复图片`

主表默认 9 列：

`日期、车号、驾驶员、重量、货物名称、装货地、收货地、备注、原图`

重量只从过磅单的 `净重` 或 `结算重量` 取值；两者视为同等做账重量，正常应一致。`毛重`、`皮重`、`空重` 不用于最终重量填写，也不相减推导重量。

默认情况下，点击“一键出表”会直接使用当前出表设置生成 Excel，不再每次弹出表格列确认窗口。

- 需要特殊批次多一列、改列名、调顺序、改列宽时，先点左侧“出表设置”调整，再点“一键出表”。
- 自定义列模板会保存为 `excel_template.json`，下次打开软件仍可继续用。
- 原图方式默认是“外部原图链接”：Excel 只放可点击文件名，原图复制到同名 `_原图` 文件夹，表格更轻、更好传。
- 最终必须保留 `原图` 列，否则不能追溯对应原图。
- 出表完成后会打开“交付工作台”，汇总待复核、缺重量、路线待核、重复图片和最终文件入口。

## 3. 使用步骤

1. 双击 `做账执行工具.exe`。
2. 软件会自动创建当天批次总目录，例如 `2026-06-02_保谊达做账表`，把本批单据图片放进里面的 `待处理图片` 文件夹，或点“导入图片”选择本批图片。
3. OCR 引擎默认保持“智谱”；右侧下方配置会跟随引擎切换，智谱可选综合、手写、磅单、表格、票据/单据等场景，需要时也可切到阿里云、百度、腾讯云或本地 PaddleOCR。
4. `ZHIPU API Key` 默认不填写；第一次使用在线 OCR 时，在框里填入 Key，并保持勾选“记住 Key（仅本机）”。
5. 需要查看 OCR 推荐、导入云 Key、检查环境、单独 OCR 或安装本地 OCR 时，点“OCR 设置”。
6. 检查左侧“今日批次状态”和“出表设置”，确认无误后点击“一键出表”。

结果会自动保存到当天批次总目录里的 `输出结果` 文件夹，不需要手动设置输出目录。

执行时中间流程区会显示进度条、百分比、预计剩余时间和滚动终端日志。OCR 阶段按图片张数推进，解析和 Excel 生成按阶段推进。

已有 `paddle_ocr_raw.json` 时，软件只会在它覆盖当前全部图片、没有失败、没有空文本、没有混入旧图片时跳过整批 OCR；否则会自动重跑 OCR，不会拿失败 OCR 继续生成空白表。
左侧“今日批次状态”会显示图片、OCR、复核、交付状态，以及当前最需要处理的问题和下一步动作。需要调整列、列宽或原图方式时，先点“出表设置”，保存后再点“一键出表”。

### 扫描仪自动导入

安装版会在程序目录旁创建 `扫描导入` 文件夹。扫描仪可直接把图片保存到下面任一结构：

```text
扫描导入\2026-06-24\图片
扫描导入\2026-06-24\待处理图片\图片
```

软件启动后会自动监听 `扫描导入`，发现新图片并等待文件写入稳定后，会弹窗显示图片数量和批次路径。按钮含义：

- `立即一键出表`：自动把该批次设为当前图片目录，输出到同批次下的 `输出结果`，然后走原有“一键出表”全链路。
- `稍后提醒`：本次先不处理，稍后再次提醒。
- `忽略本批`：记录忽略状态，不再反复弹窗。

扫描监听只负责发现和选择目录，不会绕过 OCR 预检、空 OCR 硬停止、疑问复核和 Excel 规则。

### 做账规则和纠错

点左侧“规则管理”可以直接看到软件执行中的内置做账路线规则，例如钢渣、卷子板、线材、锌锭、钢坯等货物对应的装货地和收货地。内置规则是只读规则，不能直接删除或改写；如果某个客户批次需要临时覆盖，点“新增”建立人工纠错/路线覆盖规则。

“一键出表”执行顺序固定为：先按规则管理里明文显示的内置做账规则回填装货地、收货地，再应用用户新增的人工纠错/路线覆盖规则。人工规则与内置路线冲突时，以人工规则为准，并在主表 `备注` 写入纠错留痕。这样既能看清软件默认依据，也能保留人工修正的原因。

规则管理里会显示规则来源、内置规则数量、人工启用规则数量、停用或删除的历史数量，以及选中规则的生效位置和冲突处理方式。疑问复核台也会显示当前行命中过哪些内置规则或人工规则。

点击“疑问复核”可以连续处理疑问行；保存修正或确认无误后会跳到下一条待复核记录；仍不能确认可点“仍待核”。原图预览可直接点击打开；键盘支持保存修正、确认无误、打开原图、上一条/下一条和关闭窗口。

软件启动后会自动检查 GitHub Release 是否有新版；发现新版时会提示下载并重启更新。也可以点左侧“检查更新”手动检查，下载进度会显示在中间进度条和日志里；替换前旧版会备份到程序旁边的 `更新备份` 文件夹。自动更新要求当前电脑能访问该 GitHub Release；如果仓库保持私有，同事电脑必须有访问权限，否则会提示更新源不可访问。

默认生成后会同时得到：

- `运输录入_<日期范围>.xlsx`
- `运输录入_<日期范围>_原图` 文件夹
- 文件夹里的 `原图索引.csv`

传给同事时，把 Excel 和 `_原图` 文件夹放在一起发送。Excel 里的 `原图` 列是相对链接，`原图索引.csv` 也记录相对路径，不依赖本机用户目录下的绝对地址。

筛选、排序或移动行时，`原图` 链接单元格会跟着该行走。外部图片文件名是在生成 Excel 时固定下来的，不会因为 Excel 里筛选或排序而自动重命名。

## 4. GPS 数据

右上角默认显示 GPS 快照；本机保存过 GPS 授权后，软件启动时会自动刷新一次。点击右上角 GPS 面板或打开“GPS 设置”也会立即刷新。

要让 GPS 真正更新，在“GPS 设置”里点“配置授权”，填入后台接口地址、请求方式、`Authorization` 或 `Cookie`，再点“保存并刷新”。如果开发者工具里显示该接口是 `POST`，还要把“载荷”页里的请求体填到软件的“请求体”框。授权保存在本机配置里，软件会请求 GPS 接口并按后台状态规则统计总车、在线、离线、行驶、停止、报警。

GPS 后台授权不要硬编码进 exe，也不要随便发给外部人员。

## 5. OCR 怎么选

- 先在主界面右侧选择 OCR 引擎；下方配置会随引擎切换。选择智谱时可选综合、手写、磅单、表格、票据/单据等场景；选择本地 PaddleOCR 时显示最强、均衡、极速档位。
- 普通分享给别人：用“智谱”，对方不需要安装本地 OCR 环境；发送时把启动 EXE 和同级 `_internal` 文件夹一起压缩。
- 对方机器有强 NVIDIA GPU，但没装 PaddleOCR / PaddlePaddle GPU：如果仍选择智谱，就直接在线跑；如果选择本地 PaddleOCR，软件会先尝试联网补齐本地环境，不会偷偷切回在线 OCR。
- 对方机器有 5090 / 高显存 NVIDIA GPU，并且 PaddleOCR、PaddlePaddle GPU、CUDA、`paddle.utils.run_check()` 都通过：切到“本地 PaddleOCR”，默认使用“最强模式：PP-OCRv6 medium（默认，准确率最高）”。

软件的“OCR 设置”里可以查看推荐、方案库、检查环境、单独运行 OCR、安装本地 OCR 或查看官方资料。检测到 5090 只代表硬件强，不代表本地 OCR 已装好；本地 OCR 还必须找到已安装 PaddleOCR 和 GPU 版 PaddlePaddle 的 `python.exe`。

当前可直接调用的主方案：

- 智谱：默认方案，配置项包含综合识别、手写识别、磅单识别、表格识别、票据/单据识别，适合直接发同事使用。
- 阿里云：已接入 OCR 引擎，可在下方接口列表选择手写、通用、表格、票据等接口；需要阿里云 AccessKey。
- 百度：已接入 OCR 引擎，可在下方接口列表选择手写、通用、磅单、卡证、车辆等接口；需要百度 OCR API Key/Secret Key。
- 腾讯云：已接入 OCR 引擎，可在下方接口列表选择手写、印刷、高精、表格、车辆等接口；需要腾讯云 SecretId/SecretKey。
- 本地 PaddleOCR PP-OCRv6 medium/small/tiny：本地高级方案，适合 5090 这类强显卡配置完整后批量跑，默认使用准确率最高的 medium。

腾讯云通用手写体 OCR 小样本测试：

```powershell
$ProjectRoot = "<项目根目录>"
Set-Location "$ProjectRoot\项目资料\开发源码"
python run_tencent_ocr_test.py --configure
python run_tencent_ocr_test.py --input "$ProjectRoot\2026-06-02_保谊达做账表\待处理图片" --limit 6
```

`--configure` 会隐藏输入 SecretKey，并优先用 Windows DPAPI 保存到本机配置；不要把 SecretKey 粘到聊天、文档、命令行历史或 Excel 里。

方案库里的备选方向：

- 通义 Qwen-OCR / Qwen-VL：优先作为下一步在线备选和疑问行复核。
- PaddleOCR PP-StructureV3 / PP-ChatOCRv4：适合表格、版式和关键信息抽取增强。
- 本地 Qwen3-VL-30B-A3B-Instruct / Qwen3-VL-32B-Instruct：本机 32GB 显存优先考虑的视觉复核模型，适合疑问行、手写备注、复杂版式和抽样对比，不默认全量跑。
- 本地 Qwen2.5-VL-32B / GOT-OCR2 / Surya：作为兼容备选和对照基线；Qwen2.5-VL 不是当前主推。
- Mistral OCR：更偏 PDF/文档解析场景，可作为海外或 PDF 备选。

规则：不要默认多引擎全量乱跑。先用主引擎跑整批，再对疑问行用备选方案复核，最后人工确认。

## 6. 本地 PaddleOCR 可选项

本地 PaddleOCR 是高级模式，不是普通分享的前置条件。

选择本地 PaddleOCR 后，软件会优先使用已有 Python；找不到 Python 时会尝试通过 Windows `winget` 安装 Python 3.12，然后安装 PaddleOCR 和 PaddlePaddle。软件只会把 NVIDIA 显卡当作 Paddle GPU 候选；虚拟机显卡、核显或 Microsoft Basic Render Driver 会走 CPU 版 PaddlePaddle。CPU 本地 OCR 可以运行，只是速度会比独立显卡慢。

安装前软件会先显示本机判断结果：调用 `gpu:0` 还是 `cpu`。50 系显卡会按 PaddleOCR 官方 50-series wheel 路线处理；GPU 检查没通过但 PaddleOCR/PaddlePaddle 基础包可用时，不算失败，会明确提示使用 CPU 模式。

档位：

- 最强模式 [CPU/GPU]：PP-OCRv6 medium，默认档，准确率优先。
- 均衡模式 [CPU/GPU]：PP-OCRv6 small，速度和准确率平衡。
- 极速模式 [CPU/GPU]：PP-OCRv6 tiny，速度优先，准确率低于 medium。

默认不要为了速度手动改掉 medium；如果某一档初始化失败，软件会自动换到下一档，不需要用户看到进程退出码后手动猜原因。

## 7. 下载入口

`发布下载页.html` 是本地下载页模板。稳定版发布时应把 `做账执行工具.exe` 和同级 `_internal` 文件夹一起压缩成 zip，再放到网盘、对象存储或内网 HTTP 目录。

浏览器不能安全地“下载后自动执行环境安装脚本”。本地 OCR 环境补全已经做进 exe 的“补全本地 OCR”按钮里。

## 8. 常见问题

### 在线 OCR 报 API Key 错误

确认 Key 有效，并且不要重复填写 `Bearer `。软件兼容裸 Key 和 `Bearer Key` 两种写法。

### 点击一键出表后提示 OCR 没跑通

这是保护机制。OCR 返回失败、空文本或网络/API Key 不可用时，软件会停止生成 Excel，避免输出一张看起来有行数但字段全错的表。先按弹窗提示处理 Key、网络或本地 OCR 环境，再重新点“一键出表”。

### 本地 OCR 报 paddleocr=False

说明选中的 Python 没装 PaddleOCR。点击软件里的“补全本地 OCR”，或手动运行：

```powershell
python -m pip install --upgrade paddleocr
```

### CUDA 不可用

`paddle.is_compiled_with_cuda()` 如果是 `False`，说明当前环境不是 GPU 版 PaddlePaddle。

50 系显卡必须按 PaddleOCR / PaddlePaddle 官方当前说明安装对应 GPU wheel。不要随便复制旧机器的 CUDA 包；本机默认预装/预下载 PP-OCRv6 medium、small、tiny 三档模型。

### 原图链接打不开

确认 Excel 旁边的 `_原图` 文件夹没有被改名、移动或漏发。

### 格内嵌图模式图片打不开或不在单元格内

必须使用新版 Excel / Excel 365 打开。旧版 Excel 对单元格图片兼容性不足，不能作为降低交付标准的理由。
